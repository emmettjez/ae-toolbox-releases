Order of operations

Five pairs of tools where the order changes the result, and the reason in each case.

Most of the panel can be run in any order. These five cannot, and each has a mechanical reason rather than a stylistic one.

Relink, then Gather, then Sort disk

Relink first — a missing item has no path, so nothing downstream can decide where its file belongs. Gather second, because Sort disk only files what is already inside the project directory and Gather is what puts it there. Sort disk last, on a set of files that is finally complete and findable.

Consolidate before Organize

Consolidate matches an imported .aep's items to files you already have while the imported project's own folder still says which is which. Run Organize first and both sets are filed by kind into the same folders — after that nothing can tell the copy from the original. Organize raises its own note when it sees an imported project, and the note says this.

Declare masters before Unused, Reduce or Collect

Unused means not reachable from a master. Until you have declared them, a comp with nothing above it looks exactly like the one you deliver, so Unused removes no comps at all, Reduce has nothing to reduce to, and Collect has nothing to seed its basket from. See Set up each project.

Reduce before Collect — or use Collect's own Only these comps

Collect copies what the project holds. If the project still holds three abandoned versions of the build, so does the folder you hand over. Either Reduce the project first, or let Collect do it on the copy with Only these comps — which is the safer of the two, because your working project is left alone.

Comp settings before Resize

Resize works out its scale factor from each comp's current dimensions. Conform the sizes and frame rates first with Comp settings, so the factor is measured from the size you meant rather than from one that drifted — otherwise a comp that was 1918 px wide scales to something that is not the number you asked for.

And one that is not an order

Organize and Sort disk read the two halves of the same template but touch nothing in common — one moves items in the Project panel, the other moves files on disk. Run either without the other, in whichever order suits you.
