When something looks wrong

The messages and dead ends people hit most, what each one is actually telling you, and what to do about it.

Most of these are Toolbox refusing to guess. The message names the reason; this page names the fix.

It says "nothing to do", but I can see things it should be doing

Read what the tool's own scope was. A tool that ran on a Selection planned whole-project and then intersected with your selection, so a selection that cannot hold the work leaves nothing behind. Switch the sheet to Whole project and look again. If the count is still zero, the tool is telling you the project already matches — Organize on an organized project genuinely has nothing to move.

Ran, but the result could not be read is a different message and means something else: the work may have happened, but the report After Effects returned could not be parsed. Press Scan in the header and check the project.

A button is dim

It needs a selection you do not have. Buttons that need one dim rather than disappear, so you learn they exist — and point at the button: a disabled control says why in its tooltip. Select something in the Project panel and it lights up.

I pressed a tool and nothing happened

Look at the tile you pressed — it reads reading…. The opening scan deliberately skips expressions, because on a 1,445-item project reading them was 92% of the scan time. The first tool that needs expressions fetches them on the press, and that is the pause.

A row says 0, so I assume that part is dead

Not necessarily. Some counts are lower bounds measured before anything moves, and one of them cannot be counted in advance at all: whether a folder ends up empty is only knowable after the moves, so the empty-folder sweep contributes no number. A row at 0 with options under it, or a row whose work is created by the rest of the run, is still live.

Sort disk is off and says why

Either the project's directory is Unmanaged — This project's directory is unmanaged — Toolbox does not rearrange files on disk here. Switch it to Managed in the header if it should. — or the project is relocated (below). Unmanaged is the setting that says this project lives inside somebody else's job tree, and re-filing every file inside it would be rearranging other people's work. See Set up each project.

"Almost every file sits outside this directory"

Two very different things produce it, which is why Toolbox will not pick one for you. Either the project was moved away from its footage — Relink it — or its footage was never meant to live beside it, because this is one project among many in a larger job — switch the directory to Unmanaged. Gather and Sort disk block until you do one or the other, because filing "strays" that are actually the whole job would be wrong either way.

"Save the project first"

Save the project first — where its files belong is measured from where it lives. An unsaved project has no path, so there is no project directory, no way to tell inside from outside, and nothing for a disk tool to measure against. Save it and press the tools again. The same rule stops Update assets climbing — project not saved — nothing climbs — and stops a background render, which opens the project from disk.

"No masters declared"

Working as intended, and the most consequential thing you can fix. Unused means not reachable from a master, so until you have said which comps are the point of the project, a comp with nothing above it is indistinguishable from the one you deliver. Unused removes footage and solids only, Reduce has nothing to reduce to, and Organize files nothing as unused. Select your deliverables, then Masters ▾ › + add selected — see Set up each project.

Organize filed my master comps as precomps

Then something in the project uses them. A comp that another comp puts on a layer is a precomp, by the graph, whatever it is called — a comp sitting in the render queue does not count as a master either. Declare the deliverables as Masters and run Organize again; top-level comps go to comps, and comps nothing uses go to comps/other once masters exist.

The search seems hung

It is not, and there are two ways to stop it. Every search and scan draws its own Stop button while it is running. And closing the sheet stops the search it started — that was not always true: a cancelled Relink once kept walking 940,475 files with nowhere to put the answer. A stopped search reports a partial answer and applies nothing; it is never reported as "found nothing".

Render has no destination

No destination — this project's directory is unmanaged, so there is no default render folder; pick one with Browse… On a Managed project the default is <project>/render. Unmanaged deliberately has no default, because creating a render directory inside a tree you have said is not Toolbox's to shape is exactly the thing the setting turns off. Pick a destination once and it is remembered against the job.

My update isn't showing up

A red strip at the top of the panel that cannot be dismissed means a shadow install: another copy of the extension is registered on this machine, and After Effects is running that one. Another copy of this panel is installed. The strip names the folder to move and tells you to restart After Effects — extensions are only registered at launch, so removing the folder changes nothing until you do. It outranks update news on purpose: "0.8.2 is available" is noise when nothing you install will appear.

The project forgot its render destination and template

You moved it to another directory. What Toolbox remembers per job is keyed on the directory plus the filename with version and copy markers stripped, so spot_v01.aep and spot_v02.aep in one directory share their settings — but the same file in a new directory is a new job. That is deliberate: the alternative is every main.aep on the machine sharing one memory. Set the destination once in the new location.

Something I asked it to leave alone was left alone, and now I want it acted on

Check the two mechanisms that do that. Protected items — anything carrying [KEEP] in its Comment, and everything under a protected folder — are walked around by every verb in the panel. And the template's Always create folders are created but never filed into and never emptied. Remove the [KEEP], or take the folder off the Always create list. See Set up each project and Set up once.
